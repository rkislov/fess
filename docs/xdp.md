# Необязательный fess-xdp

`fess-xdp` — отдельный Linux-процесс, загружающий встроенную eBPF-программу
на явно выбранный сетевой интерфейс. Обычный `fess` работает без него и не получает
дополнительных привилегий. Нужны Linux 5.15+, CAP_BPF/CAP_PERFMON/CAP_NET_ADMIN и поддержка XDP
драйвером (native), либо явно выбранный generic-режим.

## Функции

- CIDR deny/allow для IPv4 и IPv6. Allow имеет приоритет и обходит rate limit.
- Фильтрация только указанных входящих TCP/UDP destination ports.
- Лимит пакетов и SYN без ACK в секунду на source IP; 0 выключает лимит.
- Независимый общий бюджет пакетов, байтов и SYN с допустимыми всплесками.
- Отдельные общий и адресный лимиты ICMP/ICMPv6 Echo Request.
- Опциональные проверки длин IP/TCP/UDP и флагов SYN+FIN/SYN+RST.
- Временные блокировки прямых клиентов после действия `block` в HTTP-WAF через локальный Unix-сокет.
- Разбор двух VLAN-тегов и до шести распространённых IPv6 extension headers.
- Счётчики пропуска и отбрасывания по каждой причине в журнале каждые 10 секунд.
- Отказ от замены уже установленной XDP-программы. Закрытие процесса снимает
  только его собственную привязку; maps и link не закрепляются в bpffs.

Программа возвращает XDP_DROP либо XDP_PASS. Она не перенаправляет трафик в AF_XDP,
не завершает TCP/TLS и не заменяет HTTP-WAF. Лимит пакетов не равен лимиту HTTP RPS.
За балансировщиком/прокси виден его source IP, а не X-Forwarded-For.

## Установка и включение

Установите отдельный пакет `fess-xdp` для своей архитектуры. Он не является
зависимостью FESS и не включается автоматически.

```sh
sudo apt install ./fess-xdp_2.1.0_amd64.deb
sudo cp /etc/fess/xdp.json.example /etc/fess/xdp.json
sudo editor /etc/fess/xdp.json
sudo fess-xdp --check --config /etc/fess/xdp.json
sudo systemctl enable --now fess-xdp
journalctl -u fess-xdp -f
```

Укажите действительное имя интерфейса вместо CHANGE_ME, защищаемые порты и свои
CIDR/лимиты. В native-режиме отсутствие поддержки драйвера приводит к явной ошибке;
если нужен generic, задайте его явно. Generic не обещает производительность native.
Порт SSH не фильтруется, если он не включён в `ports`.

Изменения конфигурации применяются `systemctl restart fess-xdp`. Перезапуск имеет
короткий промежуток без XDP-фильтра; FESS и стандартный сетевой стек продолжают
работать. Для отключения: `systemctl disable --now fess-xdp`.

## Запуск и привязка из панели

После установки пакета `fess-xdp` работает отдельный локальный контроллер
`fess-xdp-control.service`. Он сам не загружает и не привязывает eBPF-программу.
Администратору доступен раздел **Настройки → XDP**:

1. Выберите интерфейс из списка интерфейсов сервера и режим native/generic.
2. Укажите TCP/UDP-порты, CIDR и параметры нужных блоков защиты.
3. **Сохранить** записывает `/etc/fess/xdp.json`, сохраняя фильтр остановленным.
4. **Сохранить и запустить с привязкой** запускает `fess-xdp.service` и проверяет
   фактическую привязку программы к выбранному интерфейсу.
5. **Остановить и снять фильтр** останавливает сервис и снимает его собственную
   привязку. После остановки можно изменить интерфейс и параметры.

Статус показывает состояние systemd, интерфейс и ID XDP-программы из ядра.
Чужой фильтр не заменяется. Изменения работающей конфигурации возвращают конфликт;
для их применения требуется остановка и повторный запуск с кратким промежутком
без XDP. Другие уровни WAF продолжают работать. Запуск из панели не включает
автозапуск фильтра после перезагрузки; для этого можно отдельно включить
`systemctl enable fess-xdp`.

Контроллер слушает только Unix-сокет `/run/fess-xdp-control/control.sock`
с правами `root:fess 0660`; каталог имеет права `0750`. Основной FESS обращается
к нему без BPF/root-привилегий. Контроллер разрешает только чтение/сохранение
XDP-конфигурации и start/stop фиксированного `fess-xdp.service`, без shell и
произвольных команд. Запись конфигурации атомарная, права файла `0600`.
Внешние API `/api/v1/settings/xdp`, `/status`, `/interfaces`, `/start`, `/stop`
доступны только роли `admin`. `FESS_XDP_CONTROL_SOCKET` позволяет изменить путь
сокета на стороне FESS при нестандартном размещении.

Если контроллер недоступен, панель сообщает об этом и блокирует действия.
Для старой установки после обновления пакета: `systemctl enable --now fess-xdp-control`.

## Независимые настройки защиты

Все четыре раздела необязательны и выключены по умолчанию. У каждого есть
`enabled`; отключение сохраняет параметры для последующего включения.
Полный пример: [`packaging/xdp.json.example`](../packaging/xdp.json.example).
Значения в нём иллюстративные: их следует выбирать по допустимой нагрузке сервера.
Настройки XDP редактируются в панели и сохраняются в JSON отдельно от БД HTTP-WAF.
Ручное редактирование JSON по-прежнему поддерживается.

### Общий бюджет: `global_budget`

- `packets_per_second` / `packet_burst`: скорость пополнения и ёмкость в пакетах.
- `bytes_per_second` / `byte_burst`: скорость и ёмкость в байтах Ethernet-кадра,
  доступных XDP, включая Ethernet/VLAN, без FCS и физического overhead.
- `syns_per_second` / `syn_burst`: отдельный бюджет SYN без ACK.

Это общий бюджет **всех настроенных TCP/UDP-портов выбранного интерфейса**,
включая разные IP-источники, IPv4 и IPv6. Он не хранится в LRU и не сбрасывается
сменой source IP. Размеры и скорости ограничены 1 млрд; нулевая пара выключает
соответствующее измерение. Для включённого измерения и rate, и burst должны быть
положительными. Если byte burst меньше размера пакета, этот пакет не пройдёт.

Бюджет использует token bucket, начинает с полного burst и пополняется непрерывно
по монотонному времени. Учёт общий для RX CPU, под блокировкой BPF map; это может
ограничить предельный PPS под нагрузкой, поэтому нужен замер на целевой NIC.
Проверяемые измерения списываются консервативно: отказ другого измерения или
последующего лимита на IP не возвращает уже потраченные токены.
Прежние верхнеуровневые `packets_per_second` и `syns_per_second` остаются
независимыми секундными лимитами **на источник**.

### ICMP Ping Flood: `icmp_ping`

- `packets_per_second` / `burst`: общий бюджет Echo Request.
- `per_ip_packets_per_second` / `per_ip_burst`: бюджет на source IP.

Защита работает отдельно от TCP/UDP-портов на всём выбранном интерфейсе.
Обрабатываются только IPv4 type 8/code 0 и IPv6 type 128/code 0.
Echo Reply, ошибки ICMP, Packet Too Big и NDP не расходуют эти бюджеты.
CIDR allow обходит лимиты. Пары rate/burst выключаются двумя нулями.
Общий бюджет — token bucket; адресный — эквивалентный ограничитель GCRA с
консервативным округлением интервала до наносекунды и ограниченной LRU-map
на 65536 источников. Общий бюджет проверяется первым, чтобы flood не создавал
неограниченную работу с адресными записями. Поэтому отклонённый адресным лимитом
пакет может уже израсходовать общий токен.

### Некорректные пакеты: `malformed_packets`

- `invalid_lengths`: проверять объявленную длину IPv4/IPv6, минимальный размер и
  data offset TCP, длину UDP относительно полезной нагрузки IP.
- `invalid_tcp_flags`: отбрасывать SYN+FIN и SYN+RST.

Нужно включить хотя бы одну проверку. Проверки применяются только когда удалось
определить настроенный TCP/UDP destination port. Ошибки базового IP-заголовка,
не позволяющие безопасно найти порт, усечённые VLAN/extension headers и слишком
длинные IPv6 chains остаются стеку Linux. Это сохраняет область действия защиты;
данный режим не является полной проверкой протоколов или контрольных сумм.
Ethernet padding не считается частью полезной нагрузки IP. IP-фрагменты по-прежнему
подчиняются отдельному `drop_fragments`, IPv6 jumbograms остаются Linux.

### Временные баны WAF: `temporary_blocks`

- `socket_path`: абсолютный путь Unix datagram socket (до 100 байт).
- `socket_group`: группа, которой разрешено отправлять баны; пустая строка —
  только владелец процесса XDP. С группой права сокета `0660`, без группы `0600`.
- `ttl_seconds`: срок бана после достижения порога, от 1 до 86400 секунд.
- `min_events`: сколько фактических блокировок WAF от одного IP нужно для бана
  (1..1000000; при отсутствии поля используется 1 для совместимости).
- `window_seconds`: окно накопления срабатываний (1..86400; по умолчанию 60).

Для защиты от единичного ложного срабатывания задайте, например, три события
за 30 секунд и короткий TTL. После бана накопленный счётчик сбрасывается.
Состояние порогов ограничено LRU на 65536 IP; вытеснение снижает строгость
накопления, но не создаёт ложный бан другому адресу.

При настройке в панели достаточно включить этот блок и задать TTL: стандартный
сокет автоматически обнаруживается FESS. Для ручной настройки:

1. В `xdp.json` включите `temporary_blocks.enabled`, задайте, например,
   `/run/fess-xdp/blocks.sock`, группу `fess` и TTL 60 секунд.
2. FESS по умолчанию обнаруживает `/run/fess-xdp/blocks.sock`. Для другого пути
   задайте `FESS_XDP_BLOCK_SOCKET` в `/etc/fess/fess.env`; пустое значение
   явно отключает отправку банов.
3. Перезапустите `fess-xdp` и `fess`. Пакетный systemd unit создаёт
   `/run/fess-xdp`; при ручном запуске создайте родительский каталог заранее,
   с владельцем root и без права записи для посторонних.

Бан отправляется только после фактического действия `block` правила WAF,
включая WebSocket handshake. `log`, `redirect`, `replace`, ошибки движка,
HTTP rate limit, bot challenges и отдельные threat-feed/антивирусные решения
автоматические XDP-баны не создают. Бан действует на source IP для всех
настроенных TCP/UDP-портов, а не на отдельный URL/host; для общего NAT это может
затронуть нескольких клиентов. CIDR allow имеет приоритет над баном.
HTTP IP bypass предотвращает новые события от правил WAF, но не удаляет уже
действующий XDP-бан: нужно дождаться TTL или изменить XDP allow-конфигурацию.

Клиент использует ограниченную очередь на 256 событий и не задерживает HTTP
при её переполнении. Ошибки доставки суммируются в журнале раз в 10 секунд;
WAF продолжает применять свои HTTP-решения. XDP не требует общих привилегий с
WAF: только XDP-процесс меняет BPF map. Передаётся только IP, TTL задаёт сервер.
Баны хранятся в LRU-map на 65536 адресов, истекают по монотонному времени и
сбрасываются при перезапуске XDP; при переполнении возможна эвикция до TTL.

Доверенные прокси из `WAF_TRUSTED_PROXIES` никогда не получают автоматический бан,
даже если заголовок с адресом клиента отсутствует. Адреса из forwarded headers
не отправляются в XDP. До TLS/PROXY обработки `http.Server.ConnContext` сохраняет исходного сетевого
отправителя. Поэтому включённый PROXY protocol не отключает баны для прямого HTTP,
а соединения от доверенного PROXY-отправителя и адреса, отличающиеся от реального
сетевого источника, исключаются. Loopback никогда не получает автоматический бан.
При встраивании gateway в другой HTTP server нужно устанавливать
`clientip.CaptureNetworkPeer` как `ConnContext`; без подтверждённого источника
баны при включённом PROXY protocol не отправляются.
Механизм рассчитан на прямые подключения к FESS на той же машине и интерфейсе.

Существующий файл на месте сокета не заменяется. При штатной остановке сокет
удаляется; после аварийного ручного запуска может потребоваться удалить оставшийся
сокет, предварительно убедившись, что другой XDP-процесс не работает.

### Счётчики

В **Настройки → XDP** доступны общие и пропущенные пакеты, отбрасывания по каждой
причине, PPS и Мбит/с всего интерфейса и защищаемых портов, частота SYN и Echo Request.
Здесь итоги считаются с начала текущего запуска, а скорости — по разнице снимков с
фактически прошедшим временем. Первый снимок не содержит скоростей. Перезапуск
обнуляет счётчики; данные старше 30 секунд помечаются устаревшими и скорости
скрываются. API возвращает статистику в поле `statistics` у `/settings/xdp/status`.

На **Дашборде** переключатель **Час**, **Сутки**, **Неделя** задаёт общий период
для счётчиков, разбивки отбрасываний по причинам и графика. Показаны суммарные
пакеты, пропуски, отбрасывания и их доля, объём трафика интерфейса и защищаемых
портов, пакеты защищаемых портов, SYN, Echo Request и неразобранные пакеты,
переданные стеку. График переключается между пакетами/с и Мбит/с.
FESS собирает снимки независимо от открытого браузера
и сохраняет их в таблице `xdp_samples` основной базы SQLite или PostgreSQL. История
хранится 8 дней; удаление старых записей выполняется раз в час. Выбор периода
сохраняется в браузере, сами данные переживают обновление страницы и перезапуск FESS.

Для часа шаг составляет 10 секунд, для суток — 2 минуты, для недели — 10 минут.
Средние скорости взвешены по фактической длительности измерений; пропуски не
подменяются нулевым трафиком. Итоги на дашборде получаются суммированием
`скорость × длительность измерений` для каждой точки выбранной истории,
с округлением только конечной суммы. Они включают предыдущие запуски XDP.
Рядом показана фактическая длительность измерений: при неполной истории
счётчики отражают только сохранённые данные. Средние скорости рассчитаны за
это же время. При загрузке или отсутствии истории счётчики текущего запуска
не подставляются вместо итогов периода.
Сборщик опрашивает локальный контроллер раз в 5 секунд,
повторные снимки не дублируются даже после перезапуска. Перезапуск XDP или смена
интерфейса отделяет новый участок графика, сохраняя предыдущие. Пока FESS или XDP
остановлен, история не собирается; при возобновлении сбор продолжается автоматически.
История начинается с установки версии с серверным сборщиком, прошлые измерения
из браузера не восстанавливаются.

API `GET /api/v1/dashboard/xdp/history?period=hour|day|week` возвращает диапазон,
шаг и точки графика, включая время первого/последнего снимка, интерфейс и фактическую
длительность измерений. Статистика и история доступны роли администратора.
При недоступности контроллера последние итоги остаются видимыми с предупреждением,
скорости скрываются; история из базы доступна, а подключение повторяется автоматически.

XDP-процесс раз в 10 секунд атомарно публикует снимок реальных BPF-счётчиков в
`/run/fess-xdp/stats-<pid>.json` с правами `0640`. Контроллер читает только файл
текущего `MainPID` и проверяет интерфейс. Основному WAF и контроллеру не нужны
дополнительные BPF-привилегии для чтения статистики. Снимок удаляется при остановке.
Сырые пакеты, адреса источников и содержимое запросов в снимках не сохраняются.
Весь интерфейс включает другие сервисы; защищаемые счётчики учитывают только
выбранные TCP/UDP destination ports до применения allow/deny и лимитов.

Кроме прежних счётчиков доступны `global_budget_drop`, `icmp_ping_drop`,
`malformed_drop`, `temporary_block_drop`, `frame_bytes`, `protected_packets`,
`protected_bytes`, `protected_syn`, `icmp_echo`. `malformed_pass` учитывает усечённые
и неподдержанные заголовки, которые остаются стеку. Счётчики агрегируются по CPU.

## Границы защиты

Rate state хранится в ограниченной LRU-map на 65536 source IP. Это ограничивает
память, но при большом потоке новых/поддельных адресов записи вытесняются, поэтому
адресный лимит сам по себе не гарантирует глобальную защиту от распределённого SYN flood.
Для общего ограничения предназначен независимый `global_budget`. Окна фиксированы
по монотонным секундам; на границе окна возможен двойной кратковременный burst.
Под сильной конкуренцией за атомарный счётчик пакет может быть отброшен
консервативно до исчерпания бюджета. Это не SYN proxy и не механизм проверки адреса.

По умолчанию фрагменты передаются Linux без port-based XDP-фильтрации; политику WAF
они проходят после сборки ядром. `drop_fragments=true` явно запрещает IP-фрагменты
**на всём выбранном интерфейсе**, включая фрагменты других сервисов. Атомарные
IPv6 fragment headers (без фактической фрагментации) разбираются. Неразобранные
протоколы, слишком длинные extension chains и заголовки, не позволяющие определить
защищаемый порт, передаются обычному стеку. Проверяемые некорректные TCP/UDP-пакеты
отбрасываются только при включённом `malformed_packets`. ARP, служебный ICMP/ICMPv6/NDP
и незащищаемые порты не блокируются; Echo Request ограничивается только при
включённом `icmp_ping`.

CIDR из БД и threat feeds автоматически не синхронизируются. События WAF block
передаются только при включённом `temporary_blocks` и наличии его локального сокета.
Настройки независимы, чтобы XDP можно было включать и выключать отдельно от WAF.

## Сборка и тестирование

```sh
# Нужен clang/LLVM с BPF target только на машине сборки.
BPF_CLANG=/usr/bin/clang scripts/build-xdp.sh
CGO_ENABLED=0 go build -o dist/fess-xdp ./cmd/fess-xdp
```

ELF встроен в бинарник; clang/libbpf на целевом сервере не нужны.
В GitHub CI eBPF проходит kernel verifier и packet test-run для IPv4/IPv6,
allow/deny, VLAN, extension headers, лимитов и фрагментов, общих бюджетов,
ICMP/ICMPv6, некорректных пакетов и истечения временных банов. Дополнительно фильтр
проверяется на временной veth-паре в отдельном network namespace: блокировка
целевого порта, доступность контрольного порта, отказ замены и снятие фильтра.
К физическим интерфейсам машины разработчика тесты не подключаются.

Нагрузочное сравнение XDP off/on на Linux/veth (native и generic), SYN/UDP
50 тыс. PPS и влияние на HTTP RPS: [методика и результаты](../benchmarks/xdp-linux.md).
Результаты виртуального стенда не являются оценкой предельного PPS физической NIC.

[PPS-ступени на одном Linux-runner](../benchmarks/xdp-ramp.md) отдельно измеряют
порог просадки HTTP и ограничение фактически достижимого потока. CIDR сохраняет
100% отбрасывания запрещённого источника при достигнутых примерно 300 тыс. PPS;
HTTP на этом стенде теряет более 10% baseline между 100 и 200 тыс. PPS.

Полезные первоисточники: https://docs.kernel.org/networking/af_xdp.html и
https://ebpf-go.dev/guides/getting-started/.
