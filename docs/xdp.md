# Необязательный fess-xdp

`fess-xdp` — отдельный Linux-процесс, загружающий встроенную eBPF-программу
на явно выбранный сетевой интерфейс. Обычный `fess` работает без него и не получает
дополнительных привилегий. Нужны Linux 5.15+, CAP_BPF/CAP_PERFMON/CAP_NET_ADMIN и поддержка XDP
драйвером (native), либо явно выбранный generic-режим.

## Функции

- CIDR deny/allow для IPv4 и IPv6. Allow имеет приоритет и обходит rate limit.
- Фильтрация только указанных входящих TCP/UDP destination ports.
- Лимит пакетов и SYN без ACK в секунду на source IP; 0 выключает лимит.
- Разбор двух VLAN-тегов и до шести распространённых IPv6 extension headers.
- Счётчики seen/passed/CIDR-drop/rate-drop/fragment-drop в журнале каждые 10 секунд.
- Отказ от замены уже установленной XDP-программы. Закрытие процесса снимает
  только его собственную привязку; maps и link не закрепляются в bpffs.

Программа возвращает XDP_DROP либо XDP_PASS. Она не перенаправляет трафик в AF_XDP,
не завершает TCP/TLS и не заменяет HTTP-WAF. Лимит пакетов не равен лимиту HTTP RPS.
За балансировщиком/прокси виден его source IP, а не X-Forwarded-For.

## Установка и включение

Установите отдельный пакет `fess-xdp` для своей архитектуры. Он не является
зависимостью FESS и не включается автоматически.

```sh
sudo apt install ./fess-xdp_2.1.0_amd64.deb
sudo cp /etc/fess/xdp.json.example /etc/fess/xdp.json
sudo editor /etc/fess/xdp.json
sudo fess-xdp --check --config /etc/fess/xdp.json
sudo systemctl enable --now fess-xdp
journalctl -u fess-xdp -f
```

Укажите действительное имя интерфейса вместо CHANGE_ME, защищаемые порты и свои
CIDR/лимиты. В native-режиме отсутствие поддержки драйвера приводит к явной ошибке;
если нужен generic, задайте его явно. Generic не обещает производительность native.
Порт SSH не фильтруется, если он не включён в `ports`.

Изменения конфигурации применяются `systemctl restart fess-xdp`. Перезапуск имеет
короткий промежуток без XDP-фильтра; FESS и стандартный сетевой стек продолжают
работать. Для отключения: `systemctl disable --now fess-xdp`.

## Границы защиты

Rate state хранится в ограниченной LRU-map на 65536 source IP. Это ограничивает
память, но при большом потоке новых/поддельных адресов записи вытесняются, поэтому
фильтр не гарантирует глобальную защиту от распределённого SYN flood. Окна фиксированы
по монотонным секундам; на границе окна возможен двойной кратковременный burst.
Под сильной конкуренцией за атомарный счётчик пакет может быть отброшен
консервативно до исчерпания бюджета. Это не SYN proxy и не механизм проверки адреса.

По умолчанию фрагменты передаются Linux без port-based XDP-фильтрации; политику WAF
они проходят после сборки ядром. `drop_fragments=true` явно запрещает IP-фрагменты
**на всём выбранном интерфейсе**, включая фрагменты других сервисов. Атомарные
IPv6 fragment headers (без фактической фрагментации) разбираются. Неразобранные
протоколы, слишком длинные extension chains и некорректные/усечённые заголовки
передаются обычному стеку. ARP, ICMP/ICMPv6/NDP и незащищаемые порты не блокируются.

Этот выпуск не синхронизирует CIDR с БД или threat feeds автоматически.
Настройки независимы, чтобы XDP можно было включать и выключать отдельно от WAF.

## Сборка и тестирование

```sh
# Нужен clang/LLVM с BPF target только на машине сборки.
BPF_CLANG=/usr/bin/clang scripts/build-xdp.sh
CGO_ENABLED=0 go build -o dist/fess-xdp ./cmd/fess-xdp
```

ELF встроен в бинарник; clang/libbpf на целевом сервере не нужны.
В GitHub CI eBPF проходит kernel verifier и packet test-run для IPv4/IPv6,
allow/deny, VLAN, extension headers, лимитов и фрагментов. Дополнительно фильтр
проверяется на временной veth-паре в отдельном network namespace: блокировка
целевого порта, доступность контрольного порта, отказ замены и снятие фильтра.
К физическим интерфейсам машины разработчика тесты не подключаются.

Нагрузочное сравнение XDP off/on на Linux/veth (native и generic), SYN/UDP
50 тыс. PPS и влияние на HTTP RPS: [методика и результаты](../benchmarks/xdp-linux.md).
Результаты виртуального стенда не являются оценкой предельного PPS физической NIC.

Полезные первоисточники: https://docs.kernel.org/networking/af_xdp.html и
https://ebpf-go.dev/guides/getting-started/.
