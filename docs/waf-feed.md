# Feed WAF и адаптация CrowdSec

FESS импортирует собственные профили Security Feed для generic web, Nextcloud,
Bitrix, WordPress, Tayga Mail Server, Cerber, GoPrint, GDns и Gdhcp. Это базовая
защита служебных путей HTTP-приложения в корне домена, не полный OWASP CRS.
SMTP/IMAP, IPP-содержимое, DNS и DHCP этими правилами не анализируются.

В Policies откройте «Feed WAF · CrowdSec · адаптация»:

1. Загрузите каталог по подписке (ключ из настроек Threat Feed) и импортируйте
   выбранный профиль. Для офлайн-установки скачайте JSON или ZIP в кабинете Feed.
2. Импорт создаёт выключенную политику `log` без публикации. Повторный импорт
   идентичного файла возвращает ту же политику, не сбрасывая локальные изменения.
3. Проверьте правила и ограничения. Назначьте политику тестовому сайту, включите
   её и опубликуйте. Политика сайта заменяет выбор остальных политик; профили
   содержат общие базовые правила. Режим `log` сохраняет срабатывания без блокировки.
4. Проверьте штатные входы, загрузки, API, WebDAV и другие рабочие запросы.
   После проверки переведите политику в `block` и опубликуйте вручную.

Онлайн-импорт проверяет SHA-256 файла по каталогу; офлайн ZIP проверяет все файлы
по вложенному каталогу до транзакции. Контрольная сумма защищает целостность,
не является цифровой подписью: офлайн-архивы нужно получать из доверенного Feed.
Новая версия импортируется отдельно, действующая политика не перезаписывается.
Автоматическое включение или публикация обновлений WAF не производится.

## CrowdSec AppSec YAML

Вставьте один YAML или загрузите файл до 1 МиБ, проверьте отчёт, скачайте
адаптированный JSON либо импортируйте выключенную политику `log`.
Поддерживаемый ограниченный набор:

- Логика `and` / `or`; корневой список `rules` объединяется через OR.
- Зоны `URI` (однократно декодированный `URL.Path`), `URI_FULL` (исходный путь
  с query без схемы/Host), `METHOD`, `RAW_BODY`, `HEADERS` (включая Host).
- Точные имена заголовков `variables`; несколько зон/значений проверяются через OR.
- `equals`, `contains`, `startsWith`, `endsWith`, RE2 `regex`.
- ASCII `lowercase`, `uppercase`, `trim`, `trim_left`, `trim_right`.

Иные зоны, декодеры, числовые операторы, `not`, `libinjection`, regex variables,
внешние data-файлы, сценарии CrowdSec, SecLang и неизвестные поля отклоняются.
Если не поддерживается хотя бы одно вложенное условие, отклоняется весь файл:
частичное преобразование могло бы изменить смысл правила. Не более 64 условий,
глубина до 8. Это адаптер подмножества HTTP-предикатов, не CrowdSec Engine.
Проверяйте лицензию исходного файла до дальнейшего распространения.

## Адаптация по трафику

Выберите политику `log` и обновите срабатывания за последние 24 часа. Статистика
показывает только первое совпадение в цепочке FESS. Частый запрос может быть атакой;
кандидаты не считаются автоматически ложными срабатываниями.

После проверки в журнале подтвердите легитимность запроса. Исключение сохраняется
в черновик конкретного правила: точные Host (без порта), декодированный Path и
HTTP Method. Оно пропускает это правило для всех query/body данного пути, но не
отключает остальные правила. Проверьте JSON и опубликуйте политику вручную.
Исключения можно удалить через JSON `condition_json.exceptions`. Конструктор
не преобразует условия AppSec и исключения, чтобы не потерять их при редактировании.

Источники синтаксиса и профилей: https://docs.crowdsec.net/docs/next/appsec/rules_syntax/,
https://github.com/crowdsecurity/hub, https://owasp.org/projects/crs,
https://github.com/coreruleset/plugin-registry. Приложенные тесты — регрессионные
проверки путей и условий; они не заменяют проверку развёрнутого приложения.
