# Администрирование FESS

Установка, конфигурация и переход на PostgreSQL описаны в [README](../README.md).

## Службы и обновление

```sh
systemctl status fess fess-clamd fess-freshclam
journalctl -u fess -f
journalctl -u fess-clamd -u fess-freshclam -f
```

Устанавливайте новый deb/rpm через `apt install ./пакет.deb` или
`dnf install ./пакет.rpm`. Конфигурация сохраняется; схема БД обновляется при
запуске. Перед обновлением сохраняйте резервную копию каталога данных.
Управление пакетами выполняется администратором ОС.

## Данные и резервное копирование

Основные данные: `/var/lib/fess/fess.db`, JWT-секрет и каталог `geoip`.
Для согласованной простой копии остановите FESS и скопируйте весь каталог,
включая существующие WAL/SHM-файлы SQLite. Не копируйте только `.db` у работающего
процесса. Для PostgreSQL используйте штатный `pg_dump`, отдельно сохраняйте
JWT-секрет и GeoIP. Приватные ключи сертификатов и секреты интеграций хранятся в БД.

## Доступ к панели

Панель/API слушают `127.0.0.1:8082`. SSH-туннель приведён в README.
При публикации панели наружу обеспечьте TLS и ограничьте сетевой доступ.
Роли: `admin`, `operator`, `viewer`; API использует JWT и refresh-токены.
LDAP настраивается в панели. Первичный пароль задаёт `FESS_ADMIN_PASSWORD`
до первого запуска; далее пароль меняется через управление пользователями.

## Сайты, TLS и политики

Создайте сайт с Host/FQDN, добавьте upstream и пути. Поддерживаются WebSocket,
таймауты, ограничения IP и переопределения rate limit. Сертификаты можно загрузить
или выпустить через ACME HTTP-01; для проверки ACME порт 80 должен быть доступен.
Изменения публикуются внутренними уведомлениями и применяются без перезапуска.

За внешним балансировщиком задайте `WAF_TRUSTED_PROXIES` с адресами непосредственных
TCP-соседей. Только для них FESS доверяет заголовкам реального IP.

## Антивирус

FESS отправляет тело запроса в системный `clamd` по протоколу INSTREAM через
`/run/fess-clamav/clamd.sock`. Пользователь `fess` состоит в группе `fess-av`.
Отдельная служба freshclam обновляет `/var/lib/fess-clamav`; системные библиотеки
и исполняемые файлы устанавливаются менеджером пакетов ОС.

Настройки включения, сокета, таймаута, режима ошибки, MIME и максимального размера
находятся в панели «Антивирус». По умолчанию ошибка clamd блокирует сканируемый
запрос; в журнале результат отмечается как недоступность сканера. ICAP,
HTTP-сканер и sandbox остаются дополнительными интеграциями.
Первые сигнатуры могут загружаться несколько минут. Проверяйте статус в панели.
При использовании зеркала измените `/etc/fess/freshclam.conf` и перезапустите
`fess-freshclam`.

## Наблюдение

`/healthz` — доступность процесса, `/metrics` — общие метрики API и шлюза на порту
управления. Дашборд показывает нагрузку хоста, память Go, трафик, события WAF,
антивирус и географию. Установите GeoIP MMDB через панель для данных о странах/ASN.
На системах без `/proc` часть метрик хоста недоступна.

## Журналирование и XDP

Режимы `FESS_LOG_MODE=batch|sync`, границы сохранности и метрики очереди описаны
в README. В batch-режиме штатная остановка сначала завершает HTTP-запросы, затем
сбрасывает журналы. Служба systemd даёт процессу 40 секунд до принудительной
остановки. Аварийное завершение не гарантирует сохранение очереди.

Опциональная L3/L4-служба устанавливается отдельным пакетом. См. [XDP](xdp.md).
Она не читает/меняет политики БД, не включается автоматически и не меняет права
основной службы. Перед включением задайте интерфейс, порты и лимиты явно.
