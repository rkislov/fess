# Архитектура FESS 2

Один процесс запускает management HTTP (UI/API/metrics), HTTP reverse proxy и
HTTPS reverse proxy. Политики, маршруты и сертификаты читаются из БД в неизменяемые
снимки. Уведомления внутри процесса запускают обновление снимков после записи API.
Счётчики ограничений запросов и оценки ботов работают в памяти под mutex, имеют TTL
и периодическую очистку. Их состояние сбрасывается при перезапуске.

Хранилища используют `database/sql`: PostgreSQL — исходный SQL-диалект; SQLite —
отдельная схема миграций и ограниченный адаптер используемых SQL-конструкций.
SQLite включает WAL, foreign keys, busy timeout и immediate-транзакции. SQLite и
PostgreSQL проверяются одним набором интеграционных сценариев.

Собранная клиентская панель встраивается в бинарник. Системные зависимости:
ClamAV/обновление сигнатур и корневые сертификаты ОС. Установка deb/rpm добавляет
службы systemd и непривилегированных пользователей. Для портов 80/443 процесс FESS
получает только CAP_NET_BIND_SERVICE.

Один активный экземпляр обслуживает одну установку. PostgreSQL подходит для
увеличения объёма данных, но не включает распределённые лимиты или доставку
уведомлений между процессами.
